# 甲方现场训练与推理测试手册

源码目录说明见[代码文件导航](代码文件导航.md)。训练命令已统一为 `python -m sinr_predictor.training.graph_train`；推理命令、现有模型包和数据可继续使用。

> 适用项目：单簇有向链路 GraphLSTM SINR 预测  
> Python 版本：3.12（64 位）  
> 当前主线：有向图网络 + 链路级单向 LSTM  
> 建议：到现场后严格按本文顺序操作，不要一开始就修改模型代码。

## 1. 这套项目做什么

项目每隔 1 秒把一个簇内的节点和有向链路组成一张图，使用过去 10 个时隙的数据，预测目标有向链路未来 1、2、3 秒的 SINR。

```text
过去 10 个时隙的节点状态和链路 SINR
                    ↓
          每个时隙构造一张有向图
                    ↓
          图网络提取空间关系特征
                    ↓
          LSTM 提取时间变化特征
                    ↓
        输出未来 1、2、3 秒 SINR
```

不同簇可以使用同一个 `model.pt`。不同簇的模型参数相同，但是每个簇必须分别维护自己的历史缓存。节点数量不要求固定为 16 个。

## 2. 明天现场要完成的目标

现场测试建议分为五个阶段：

1. 确认甲方电脑的 Python、NumPy、PyTorch 可以使用。
2. 确认项目源码、训练数据和已有模型完整。
3. 用小数据完成 1 轮 smoke 训练。
4. 用完整数据训练出新的 `model.pt` 和 `report.json`。
5. 加载现场训练出的模型完成推理。

现场验收的核心闭环是：

```text
训练数据 → 训练 → 新 model.pt → 加载模型 → 推理结果
```

## 10. 训练报告重点看什么

`report.json` 中重点关注：

### `best_epoch`

验证集表现最好的训练轮次。

### `best_validation_rmse_db`

最佳验证集 RMSE，单位 dB。

### `history`

每一轮的训练损失和验证 RMSE。应观察是否总体下降，而不是要求每一轮都下降。

### `test.graph_lstm.overall_rmse_db`

GraphLSTM在独立测试集上的整体RMSE。

### `test.persistence.overall_rmse_db`

“最近一次SINR保持不变”的简单基线。必须和GraphLSTM一起看，不能只展示神经网络结果。

### `availability`

满足预测条件的链路比例。

### `target_missing_ratio`

未来真实标签的缺失比例。

不同电脑、PyTorch版本和硬件上重新训练，结果可能有小幅差异，不要求和原报告逐位相同。

## 12. 推理状态码

### 请求级状态

| 状态码 | 含义 |
| --- | --- |
| 0 | 请求处理成功 |
| 1 | 请求格式或数据无效 |
| 2 | 模型不可用或推理失败 |

### 单条预测结果状态

| 状态码 | 含义 | 现场重点检查 |
| --- | --- | --- |
| 0 | 成功 | `predicted_value`应是有限数值 |
| 2 | 历史不足 | 是否已积累足够时隙 |
| 3 | 观测过期 | 节点或链路是否超过2秒未更新 |
| 4 | 不可用 | 端点不存在、节点离簇或必要字段缺失 |

## 13. 连续在线推理的重要要求

命令行适合验证一个JSON文件，不适合每秒重新启动一次。

真实在线推理必须长期复用同一个`Predictor`：

```python
from sinr_predictor import Predictor

predictor = Predictor.from_model_bundle(
    "outputs/onsite_formal_model/model.pt",
    device="cpu",
)

for current_slot_request in incoming_requests:
    response = predictor.predict(current_slot_request)
    print(response.to_dict())
```

如果每个时隙都重新创建`Predictor`，历史缓存会清空，程序会一直返回“历史不足”。

当前规则：

- 使用最近10个时隙。
- 至少8个SINR时隙需要有有效观测。
- 最多连续缺失2个时隙。
- 节点或链路超过2秒未更新会过期。
- 节点超过5秒未观测后再出现，会开启新的连续会话。
- 进程重启后内存历史会丢失，需要重新预热。

## 14. 模型输入必须注意的单位

| 字段 | 要求 |
| --- | --- |
| 时间 | 整数毫秒 |
| 时隙 | 当前配置为1000 ms |
| SINR | dB |
| 经纬度 | WGS84角度 |
| 高度 | 米，需明确椭球高或海拔 |
| 速度 | NED坐标，米/秒，Down向下为正 |
| 加速度 | NED坐标，米/秒² |
| 姿态 | 度 |

不要把缺失SINR填成0。正确做法是本时隙不写该条链路记录。

`A→B`和`B→A`是两条不同的有向链路，不能相互代替。

## 17. 常见错误及处理

### 错误：找不到`py`

```text
'py' 不是内部或外部命令
```

处理：确认Python 3.12已安装，并勾选安装程序中的Python Launcher或PATH选项。也可以使用甲方Python解释器的完整路径。

### 错误：`No module named sinr_predictor`

使用虚拟环境时重新执行：

```powershell
py -3.12 scripts\setup_env.py
```

不使用虚拟环境时执行：

```powershell
py -3.12 -m pip install -e .
```

### 错误：`No module named torch`或`numpy`

说明依赖未安装到当前正在使用的Python。用同一个解释器执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt `
  --index-url https://download.pytorch.org/whl/cpu `
  --extra-index-url https://pypi.org/simple
```

### 错误：文件不存在

先确认当前目录：

```powershell
Get-Location
```

必须位于包含`pyproject.toml`的`lstm_new`目录。

### 错误：模型加载失败

检查：

```powershell
Test-Path outputs\onsite_formal_model\model.pt
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__)"
```

不要用文本编辑器修改`model.pt`。

### 错误：训练出现内存不足

先降低batch size：

```powershell
--batch-size 2
```

还不够时增加采样间隔：

```powershell
--stride-steps 20
```

现场第一次测试不要直接使用`stride-steps 1`。

### 错误：一直返回历史不足

检查：

- 是否一直复用同一个`Predictor`。
- 是否已经积累至少8个有效时隙。
- `A→B`方向是否有SINR记录。
- 是否错误地每秒重启程序。
- 节点是否仍在簇内。

### 错误：观测过期

检查：

- 时间戳单位是不是毫秒。
- 数据是否超过2秒没有更新。
- 是否把秒时间戳误当成毫秒时间戳。

### 错误：请求无效

检查：

- 是否出现未知字段。
- ID是否为空或超过36字节。
- 同一节点、同一时间是否有两条不同记录。
- 是否存在`A→A`自环链路。
- 数值中是否有`NaN`或`Infinity`。

## 19. 甲方常见问题的简短回答

### 是否固定节点数量？

不固定。模型支持不同节点数量的图。

### 不同簇是否需要不同模型？

不需要。所有簇可以加载同一个模型，但历史缓存必须隔离。

### 图网络和LSTM是不是两个模型？

不是两个独立训练模型，而是一个端到端GraphLSTM。图网络提取空间关系，LSTM提取时间变化。

### 为什么刚启动没有预测值？

需要先积累足够的历史时隙，建议完整积累10个时隙。

### `report.json`和`prediction.json`是什么？

- `model.pt`：模型本体，推理必须使用。
- `report.json`：训练评估报告，建议保留。
- `prediction.json`：一次推理结果，可以重新生成。
