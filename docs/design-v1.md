# 预测算法第一版代码设计

本文保留 v0.1 基线阶段的设计记录。v0.2 已实现神经网络和训练评估，当前实现见 [核心算法设计](algorithm.md)。

本版交付一个可运行、可测试的 Python 3.12 算法包，解决数据到预测结果的完整接口流程。数值后端为最近观测保持，后续图空间编码和 LSTM 复用同一请求编排与历史处理层。

## 处理链

```text
请求接收及基准时间确定
  → 严格字段与时间校验
  → 整批冲突检查后写入双时间历史缓存
  → 保留时长清理
  → 最近 K 个历史图快照
  → 按有序端点提取查询窗口及连续运行区间
  → 资格判定
  → 合格查询组成后端批次
  → 后端返回 Q × H 的 dB 数值
  → 检查后端形状、有限值和目标时效
  → 按原查询顺序封装逐步结果
```

`Predictor` 为单簇有状态对象；`ModelConfig` 为不可变配置；`HistoryCache` 保存原始记录与接收时间；图与查询窗口是每次请求的派生数据。一个实例通过锁串行维护自身状态，多簇应分实例运行。簇头在线记录缺少可靠源端观测时间时，由 `Predictor` 将本次服务端接收时间写入缺失的 `observation_time_ms`；离线数据不使用该默认。

## 时间与历史

历史网格为 `t0-(K-1)Δt, ..., t0`。每个网格点只使用 `observation_time_ms <= grid_time_ms` 且 `arrived_at_ms <= cutoff_ms` 的记录。当前截止时间为接收时刻 `t0`。晚到记录能改变后续窗口，但不能进入既有截止条件的快照。

节点键为 `node_id`，关系键为 `(source_id, destination_id)`，二者都按观测时间保存。相同键和时间的冲突不依据数组顺序选择胜者，而是拒绝整批，避免重排输入造成不同输出。

节点成员状态由最新可见节点记录决定。连续运行区间的起点来自初次观测、退出后重新加入、或两条节点记录间隔超过连续性阈值。查询窗口以当前两个端点连续区间起点的较晚者为界；更早的图即使存在旧测量也不能贡献该查询的有效历史。

原始缓存当前为内存字典，按时长清理，空间用量仍随保留范围内的观测数量增长。对高频大规模簇的性能和容量未作验收；后续可在缓存接口内部替换为索引序列或环形缓冲区。

## 特征结构

每个图快照包含按稳定 ID 排序的节点、按有序端点排序的边及网格时间。下游建立张量行号时必须保留 ID 到行号映射。

节点连续特征共 15 维：ECEF 位置 3 维、ECEF 速度 3 维、可选 ECEF 加速度 3 维、俯仰/偏航/滚转的正余弦 6 维；同时保留逐维掩码、观测年龄和新观测标记。

有向边连续特征共 8 维：接收端减发送端的相对位置 3 维、相对速度 3 维、距离 1 维、历史 SINR 1 维；同时保留掩码、SINR 年龄和新测量标记。缺失数值可以用有限零占位，但掩码为假。加速度若缺少任一分量，则整个旋转后的加速度向量均标记缺失。

空间图仅包含当前有效端点。没有 SINR 历史的查询边仍可具备几何特征，但第一版不允许据此绕过历史要求。所有特征目前保留物理尺度，后续训练再拟合标准化参数。

## 资格判定

| 条件 | 结果状态 |
| --- | --- |
| 自环查询、端点不存在或退出、必要运动字段缺失 | 4 不可用 |
| 当前必要节点状态或当前运行区间内最近 SINR 超龄 | 3 观测过期 |
| 当前区间无 SINR、观测比例不足或连续缺口过长 | 2 历史不足 |
| 上述检查均通过 | 0 成功候选 |

新测量覆盖比例按历史网格区间 `(grid-Δt, grid]` 是否有有效 SINR 计算；同一测量跨网格保持不反复计数。有效性阈值是配置项，并非经真实数据验证后的固定业务标准。

## 后端协议

```python
def predict(windows: Sequence[QueryWindow], config: ModelConfig) -> Sequence[Sequence[float]]:
    ...
```

输入只包含通过资格判定的查询，输出为 `[有效查询数, 未来步数]`，单位 dB。协议返回 Python 数值；张量后端需转换到普通序列。返回维度错误、非有限值、超出 FLOAT32 范围或后端异常，统一返回请求级模型不可用。

当前 `PersistenceBackend` 读取窗口内最近有效 SINR，并重复 H 次。该实现既不训练参数，也不推测未知链路。后续后端需实现节点与关系编码、空间图消息聚合、查询关系序列、LSTM 与多步输出头，并在进入此协议前完成反标准化。

模型结构接入后，离线训练另增 `dataset.py`、`model.py`、`train.py`、`evaluate.py` 与模型包读写模块。它们未在本版以空文件或假训练流程代替。

## 输出与交付边界

外部字典字段严格使用接口文档名称，不额外附加诊断字段。内部 `diagnostic` 供调用方日志记录；无效结果数值为 `None/null`。每条查询输出 H 个目标时刻，包括不合格查询的状态记录。

本版包括进程内调用和 JSON 文件 CLI；不绑定 HTTP、消息队列、TCP 二进制或数据库。正式部署需确定字节序、无效 FLOAT32 占位、指标编码、时间同步、高度参考基准、会话重启标识、窗口阈值及验收数据。

合成数据只证明流程可运行。真实预测精度、不同规模泛化、训练收益和端侧耗时须在下一阶段用独立任务数据评价。
