## 1. 一句话介绍项目

每隔1秒把一个簇内的节点和有向链路组成一张图，使用过去10个时隙的节点状态和链路SINR，预测目标链路未来1、2、3秒的SINR。

```text
过去10张图 → 图网络提取空间关系 → LSTM提取时间变化 → 未来3步SINR
```

不同簇使用同一个模型，但是每个簇分别维护自己的历史。

## 12. 状态码速查

### 请求级

| 状态 | 含义 |
| ---: | --- |
| 0 | 请求处理成功 |
| 1 | 请求格式或数据无效 |
| 2 | 模型不可用或推理异常 |

### 单条结果

| 状态 | 含义 | 先检查什么 |
| ---: | --- | --- |
| 0 | 成功 | 预测值是否为有限数值 |
| 2 | 历史不足 | 是否积累8～10个有效时隙 |
| 3 | 观测过期 | 节点或链路是否超过2秒未更新 |
| 4 | 不可用 | 端点、成员状态和必要字段 |

## 13. 训练报告重点看什么

| --- | --- |

## 17. 历史缓存要点

```text
同一个簇长期复用一个Predictor
不同簇使用不同Predictor
所有簇可以加载同一个model.pt
程序重启后历史会丢失
启动后建议积累完整10个时隙
```

不要每秒重新启动一次命令行推理，否则历史永远积累不起来。

## 18. 现场禁止操作

- 不要覆盖自带的`formal_model`。
- 不要修改48份训练数据。
- 不要一开始就改`models/graph_lstm.py`。
- 不要混用不同Python环境的`pip`和`python`。
- 不要把缺失SINR写成0、`null`或`NaN`。
- 不要把`A→B`和`B→A`当成同一条链路。
- 不要承诺已经达到甲方真实业务精度。
- 不要删除现场新生成的`model.pt`和`report.json`。

## 19. 常见报错速查

### `No module named sinr_predictor`

```powershell
py -3.12 -m pip install -e .
```

### `No module named torch`或`numpy`

说明依赖没有安装到当前Python。确认命令中的Python和pip属于同一个环境。

### 文件不存在

```powershell
Get-Location
```

必须位于包含`pyproject.toml`的目录。

### 训练出现内存不足

在训练命令后增加：

```powershell
--batch-size 2
```

仍然不足时使用：

```powershell
--stride-steps 20
```

### 一直历史不足

依次检查：

```text
是否复用同一个Predictor
是否已有8～10个有效时隙
查询方向是否有SINR
节点是否在簇内
时间戳单位是否为毫秒
```

### 观测过期

重点检查是否把“秒时间戳”直接当成“毫秒时间戳”，以及节点、链路是否超过2秒没有更新。

## 20. 甲方可能提问的简短回答

### 节点数量固定吗？

不固定，图模型支持不同节点数量。

### 每个簇都要单独训练吗？

不需要。不同簇可以共享同一个模型，但历史缓存分别维护。

### 图网络和LSTM是两个模型吗？

不是两个独立模型，而是一个端到端GraphLSTM。图网络提取空间关系，LSTM提取时间变化。

### 为什么刚启动没有结果？

模型需要过去10个时隙，启动后要先积累历史。

### 当前数据是真实数据吗？

不是，当前训练数据来自仿真平台。

### 当前精度怎么样？

仿真测试GraphLSTM整体RMSE约1.146 dB，3 dB命中率约97.7%～98.7%；但最近观测保持基线RMSE约1.045 dB，当前还不能证明图模型在真实业务上更优。

### 当前代码是否完整跑通？

图数据转换、训练、验证、测试、模型保存、重新加载和推理流程已经跑通。
